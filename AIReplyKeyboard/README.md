# AI Reply — Android AI Keyboard

An AI keyboard that reads the conversation on your screen (via Android's Accessibility
service) and suggests replies in a selectable tone — Casual, Flirty, Professional,
Funny, Direct, Spicy, Confident, Savage or Smooth — generated by any OpenAI-compatible
LLM API.

The companion app includes:

- **Setup & API settings** — provider, key, models, default tone, and a personal
  "texting style" profile the AI adapts every suggestion to. One tap loads the
  **Delhi Gen-Z (Hinglish) preset**.
- **Screenshot Analyzer** (RIZZ-style) — pick a chat or dating-profile screenshot and
  generate openers or replies with a vision model, or run a **red/green flag audit** of
  the conversation. The analyzer auto-detects what the screenshot shows (profile, chat,
  reel or feed post) and states it above the results.
- **Message Library** — offline categorized pickup lines, icebreakers, compliments,
  romantic quotes, plus POV openers, reel comments, voice-note scripts, emoji openers
  and no-reply nudges; tap to copy.
- **Mood & trap detection** (from the DMAssistant bot) — every keyboard generation is
  annotated with the other person's apparent mood (excited / dry / defensive), and
  traps like love-bombing, money talk or rejection signals trigger a warning toast
  before you send.
- **Rewrite (✎)** — type or select your own draft in the keyboard and tap ✎ to rewrite
  it in the current tone.
- **Saved replies** — long-press any suggested reply to bookmark it; manage them in the
  app's Saved Replies screen (tap to copy, long-press to delete).
- **Hinglish mode** — a settings toggle that makes every generated reply come out in
  natural Roman-script Hinglish.
- **Tone memory** — the last tone you used in a chat app is remembered for that app,
  so reopening the conversation starts in the same vibe automatically.
- **Emoji panel** — a 😊 key toggles a 44-emoji grid; tap to insert, ABC to return.
- **Long-press accents** — hold a letter (e, a, i, o, u, n, c, s, y) for accented
  variants (é, ñ, ü, …) in a small flyout.
- **Keyboard switcher** — a 🌐 key jumps to your next installed keyboard.
- **Excluded apps (privacy)** — a settings list of package names (e.g. banking apps)
  whose screens are never captured; opening one also clears the current snapshot.
- **Release signing** — `assembleRelease` signs with `release.keystore` via
  `keystore.properties` (both gitignored; back them up and change the placeholder
  password). Falls back to the debug key if the properties file is absent.
- **Play Store readiness** — see [PLAY_STORE_CHECKLIST.md](PLAY_STORE_CHECKLIST.md)
  (accessibility declaration, data-safety form, rating) and
  [PRIVACY_POLICY.md](PRIVACY_POLICY.md) (host it publicly for the listing).

## How it works

1. **ChatReaderService** (Accessibility Service) watches the foreground app and keeps a
   snapshot of the visible text in `ChatStore`.
2. **AiKeyboardService** (Input Method Service) is a full QWERTY keyboard with a tone
   chip bar and three suggestion buttons at the top.
3. Tapping **✦** sends the latest chat snapshot to the configured LLM with a
   tone-specific system prompt and displays the 3 replies. Tapping a reply inserts it
   into the text field.

## Build

Open the project folder in **Android Studio** (Hedgehog or newer), let Gradle sync,
then Run on a device or emulator. Requires JDK 17.

Or from the command line:

```bash
./gradlew assembleDebug   # APK at app/build/outputs/apk/debug/app-debug.apk
```

## Free AI with gemini-web2api (self-hosted)

[gemini-web2api](https://github.com/Sophomoresty/gemini-web2api) exposes the Gemini web
UI as an OpenAI-compatible API — no official API key, no cost. The app supports it as a
provider preset, including the screenshot analyzer (it handles `image_url` input).

On the machine that will run the server:

```bash
git clone https://github.com/Sophomoresty/gemini-web2api
cd gemini-web2api
pip install httpx
python gemini_web2api.py        # serves http://0.0.0.0:8081/v1
```

Auth is optional: the `api_keys` list in `config.json` may stay empty (then leave the
API key field blank in the app) or contain e.g. `sk-gemini` (then type that as the key).
In the app: **Setup & API settings → AI provider → gemini-web2api** — the preset fills
in everything. It defaults to `http://10.0.2.2:8081/v1`, which works from the Android
**emulator** (that address is the host machine). On a **real phone** use your computer's
Wi-Fi IP instead, e.g. `http://192.168.1.20:8081/v1` (phone and computer must be on the
same network). Plain `http://` is allowed by the app for this purpose.

Caveats: it's an unofficial wrapper around the Gemini website — Google changes can break
it, availability/rate limits are not guaranteed, and heavy use may risk the account.
For anything serious, the official Gemini/OpenAI presets are the reliable path.

## First-run setup (on the phone)

1. Open the **AI Reply** app.
2. Tap **1. Enable the keyboard** → enable "AI Reply Keyboard" in System settings.
3. Tap **2. Enable screen reading** → enable "AI Reply — Screen Reader" in Accessibility
   settings.
4. Enter your API details — pick a **provider preset** (gemini-web2api, OpenAI, official
   Gemini API, OpenRouter, or Custom) and adjust base URL, models and API key as needed.
   The API key is optional for self-hosted servers.
5. Switch your keyboard to "AI Reply Keyboard" in any chat app and tap ✦.

## Testing (all open-source, runs headless)

- **Unit tests**: `gradle testDebugUnitTest` — 16 tests covering MoodSensor,
  OfflineFallback, tones, library and provider presets (JUnit 4, runs on the JVM).
- **Emulator E2E**: the repo was verified end-to-end on a headless Android 14 emulator
  (KVM + `emulator -no-window`): app launch, all four screens, keyboard rendering,
  accessibility capture, and suggestion insertion into a real text field.
  Note: `adb shell input tap` cannot reach IME windows on a headless emulator, so a
  **debug-only** broadcast hook (`TestHookReceiver`, no-op in release builds) drives
  generate/insert from adb:
  ```bash
  adb shell am broadcast -a com.aireply.keyboard.TEST \
      -n com.aireply.keyboard/.ime.TestHookReceiver --es cmd config   # apply web2api preset
  adb shell am broadcast -a com.aireply.keyboard.TEST \
      -n com.aireply.keyboard/.ime.TestHookReceiver --es cmd generate
  adb shell am broadcast -a com.aireply.keyboard.TEST \
      -n com.aireply.keyboard/.ime.TestHookReceiver --es cmd insert --ei index 0
  ```
- **Mock LLM**: a tiny OpenAI-compatible mock (mirrors the gemini-web2api contract,
  including `image_url` parts) lets you test the full pipeline without any API key.

## Notes & caveats

- The conversation text is sent to whatever API endpoint you configure — use a
  provider you trust.
- Google Play **requires a privacy policy and extra review** for apps using the
  Accessibility API to read screen content (it's a sensitive permission). If you plan
  to publish this on Play, see the "Accessibility API" declaration requirements.
- Distributing outside Play (direct APK, F-Droid) has no such restrictions.
- Some apps (notably banking apps, and apps that flag `FLAG_SECURE`) block
  accessibility reading; suggestions simply won't appear there.
